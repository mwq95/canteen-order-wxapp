## 二、改造方案

### 2.1 方案设计

将所有数据操作收敛到两个核心云函数：
- **quickstartFunctions**: 用户认证、员工管理、系统配置
- **orderFunctions**: 订单相关、菜单相关、评价相关

### 2.2 需要新增的云函数方法

#### quickstartFunctions 新增方法

| 方法名 | 功能 | 入参 | 返回 |
|--------|------|------|------|
| getUserInfo | 获取用户信息 | openid | 用户信息(包含isVerified, role, phone, name) |
| createOrUpdateUser | 创建或更新用户 | phone, name, role | success |
| getUserSettings | 获取用户提醒设置 | phone | subscribeOrderReminder, subscribeMealReminder |
| updateUserSettings | 更新用户提醒设置 | phone, subscribeOrderReminder, subscribeMealReminder | success |
| getMenuByDate | 获取指定日期菜单 | date | 菜单数据 |
| saveMenu | 保存菜单 | date, meals | success |
| getConfigs | 获取系统配置 | - | configs集合数据 |

#### orderFunctions 新增/修改方法

| 方法名 | 功能 | 入参 | 返回 |
|--------|------|------|------|
| getTodayOrders | 获取用户当日订单 | phone, date | 各餐次订单 |
| submitOrder | 提交订单(新) | phone, date, mealType, dishes | success, orderId |
| getHistoryOrders | 获取历史订单 | phone | 订单列表(按时间倒序) |
| markOrderEvaluated | 标记订单已评价 | orderId | success |
| submitEvaluation | 提交评价(新) | orderId, phone, evaluations | success |
| getOrderStatistics | 获取订单统计 | date | totalOrders, dishStats |
| getMealOrderList | 获取当日订餐名单 | date | 各餐次订单和菜品统计 |

## 四、云函数方法实现

### 4.1 quickstartFunctions 新增方法

```javascript
// 获取用户信息
const getUserInfo = async (event, openid) => {
  try {
    const userRes = await db.collection('users').where({ _openid: openid }).get();
    if (userRes.data.length > 0) {
      const user = userRes.data[0];
      return {
        isVerified: user.isVerified || false,
        role: user.role || 'staff',
        phone: user.phone || null,
        name: user.name || null,
        userInfo: user.userInfo || null
      };
    }
    return { isVerified: false, role: 'staff', phone: null, name: null, userInfo: null };
  } catch (e) {
    return { isVerified: false, role: 'staff', phone: null, name: null, userInfo: null };
  }
};

// 创建或更新用户
const createOrUpdateUser = async (event, openid) => {
  const { phone, name, role } = event;
  try {
    const userRes = await db.collection('users').where({ _openid: openid }).get();
    const userData = { phone, name, isVerified: true, role: role || 'staff', updateTime: new Date() };
    if (userRes.data.length > 0) {
      await db.collection('users').doc(userRes.data[0]._id).update({ data: userData });
    } else {
      userData.createTime = new Date();
      await db.collection('users').add({ data: { ...userData, _openid: openid } });
    }
    return { success: true };
  } catch (e) {
    return { success: false, error: e.message };
  }
};

// 获取用户提醒设置
const getUserSettings = async (event, openid) => {
  const { phone } = event;
  try {
    const res = await db.collection('users').where({ phone }).get();
    if (res.data.length > 0) {
      return {
        subscribeOrderReminder: res.data[0].subscribeOrderReminder !== false,
        subscribeMealReminder: res.data[0].subscribeMealReminder !== false
      };
    }
    return { subscribeOrderReminder: true, subscribeMealReminder: true };
  } catch (e) {
    return { subscribeOrderReminder: true, subscribeMealReminder: true };
  }
};

// 更新用户提醒设置
const updateUserSettings = async (event, openid) => {
  const { phone, subscribeOrderReminder, subscribeMealReminder } = event;
  try {
    await db.collection('users').where({ phone }).update({
      data: { subscribeOrderReminder, subscribeMealReminder, updateTime: new Date() }
    });
    return { success: true };
  } catch (e) {
    return { success: false, error: e.message };
  }
};

// 获取菜单
const getMenuByDate = async (event) => {
  const { date } = event;
  try {
    const res = await db.collection('menus').where({ date }).get();
    return { success: true, data: res.data[0] || null };
  } catch (e) {
    return { success: false, error: e.message };
  }
};

// 保存菜单
const saveMenu = async (event, openid) => {
  const { date, meals } = event;
  try {
    const existing = await db.collection('menus').where({ date }).get();
    if (existing.data.length > 0) {
      await db.collection('menus').doc(existing.data[0]._id).update({
        data: { meals, updateTime: new Date() }
      });
    } else {
      await db.collection('menus').add({
        data: { date, meals, createTime: new Date(), updateTime: new Date() }
      });
    }
    return { success: true };
  } catch (e) {
    return { success: false, error: e.message };
  }
};
```

## 五、风险评估

| 改造项 | 风险等级 | 说明 | 应对措施 |
|--------|----------|------|----------|
| 订单查询/提交 | 高 | 核心业务逻辑 | 充分测试，特别关注phone字段 |
| 用户认证流程 | 高 | 影响所有用户登录 | 保持原有逻辑兼容 |
| 评价功能 | 中 | 非核心功能 | 测试评价流程即可 |
| 菜单管理 | 中 | 仅管理员使用 | 测试CRUD操作 |

## 六、建议实施顺序

1. **第一阶段**: 用户相关（auth.js, app.js, reminderSettings.js）
2. **第二阶段**: 订单相关（order.js, history.js, evaluate.js）
3. **第三阶段**: 管理相关（menu.js, settings.js, statistics.js, orderList.js）
4. **第四阶段**: 首页（index.js）

每阶段完成后进行充分测试再进入下一阶段。

---

## 七、注意事项

1. **openid获取**: 云函数中通过 `cloud.getWXContext().OPENID` 获取，无需前端传递
2. **phone传递**: 前端从 `app.globalData.phone` 获取，传递给需要phone的云函数
3. **向后兼容**: 已有的云函数方法不要删除，确保历史数据兼容
4. **错误处理**: 云函数中要做好try-catch，返回明确的错误信息
